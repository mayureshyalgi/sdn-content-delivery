Basics · requests, concurrency, errors

1Three clients at once

h1, h2 and h3 each download 5 MB files at the same moment, all from one address: 10.0.0.100.

2One client at a time

Pick a client. It sends GET to 10.0.0.100 and receives the file from the server the controller chooses.

3Ask for a missing file

The client asks for missing.bin. The server answers ERR 404 and nothing crashes.

Failures, congestion and policies

4Crash a server

Stops the server program. Its heartbeats stop, and after 3 s the controller marks it down and sends new clients to the others.

5Cut a link

The switch tells the controller, which deletes the old rules and moves every download to the other route.

6Jam the fast route

gen floods UDP to sink through s4 → s2 → s1. The controller measures every link each 2 s; above 70% busy counts as congested.

7Change the controller's rules

Restarts the controller (about 5 s). Clear results, run the same test again, and compare below.

8Guided tests

Each one runs by itself and repeats the automated experiments.
